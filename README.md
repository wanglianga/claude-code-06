# 星豆亲子剧场 · 儿童走失预防与找回协同系统

## 原始需求

> 增加中场休息高风险预警。页面根据儿童年龄、座位距离出口、家长是否单人带娃、是否曾离座和厕所卖品区拥堵情况，给场务生成巡查优先级。场务确认某个区域拥挤后，安保端会同步看到需要临时分流的通道；若家长随后报告走失，系统会把这些巡查记录带入找回事件，缩小最后出现范围。预警被多次触发的区域，会影响下一场演出的场务排班和临时指示牌位置。

---

面向城市亲子剧场的**儿童走失预防与找回协同页面**：覆盖家长安全服务登记 → 闸机核验入安全列表 → 场务分区座位/高风险提示/中场拥挤度巡查 → **中场休息高风险预警（按儿童年龄、座位距出口、单人带娃、家长报备离座、厕所/卖品区拥堵五因子给场务生成巡查优先级；场务确认拥挤后安保端同步临时分流通道；报案时巡查记录自动带入找回事件收窄最后出现范围；反复触发的区域进入下一场排班与临时指示牌建议）** → 家长报案自动生成找回任务并派给最近的场务、安保、服务台 → 服务台三项核验决定通知家长/护送回座/升级广播 → 散场出口拦截、监控调阅、警方协助同事件联动 → 散场复盘并生成下一场站位/厕所引导/出口提示/指示牌建议。

技术栈：**Vue 3 + TypeScript + Pinia + Vite**，纯前端 SPA（Pinia + localStorage 持久化，刷新不丢事件），生产镜像为多阶段构建的非 root nginx，自带 `/healthz` 健康检查。

## 一、一键启动（宿主 docker compose）

```bash
cp .env.example .env          # 可按需修改 CC_PUBLISH_PORT
docker compose up -d --build
```

- 容器内 nginx 监听 **8080**，通过 `${CC_PUBLISH_PORT}` 发布到宿主（默认 `3006`），无数据库/缓存等额外依赖。
- 健康检查：`curl http://localhost:3006/healthz` → `ok`（容器 HEALTHCHECK 与 compose healthcheck 均已配置）。
- 浏览器访问：`http://localhost:3006`（或 `http://host.docker.internal:3006`）。

停止与清理：

```bash
docker compose down
```

> 端口以实际环境变量为准，可用 `docker compose port app 8080` 查看映射。

## 三、推荐演示动线（关键业务流，约 5 分钟）

1. **闸机**：点待核验订单快速填入 → 「核验入场」，朵朵会出现高风险带位提示；安全列表实时增加。
2. **经理**：推进到「演出中」→「中场休息」。
3. **场务**：打开「🚨 中场高风险预警」Tab —— 三个座位分区按综合分排序（B 区紧邻被报高拥堵的家庭厕所，为高风险），逐条展示评分依据（儿童年龄、座位距出口、单人带娃、周边厕所/卖品拥堵）。
4. **家长端**：选订单 `DD20260910001`（豆包，A 区单人带娃）→ 点「孩子临时离开座位」报备去卖品区 → 回到场务端可见 A 区预警因"离座未归"升级。
5. **场务**：在 B 区预警卡勾选「确认该区域拥挤」、巡查区域选**家庭厕所**、填写说明后提交：
   - **安保端**顶部自动出现「🔀 临时分流通道」：家庭厕所 → 东侧出口（最近出口），地图上有流动分流箭头；安保可到场打卡、填写处置后关闭通道。
   - 多次让家庭厕所人流"畅通→拥挤"波动，可看到该预警**触发次数**累计（经理端表格同步）。
6. **家长端**：仍选 `DD20260910001`（豆包）→「报告孩子不见」，最后位置选**卖品区**：
   - 事件时间线出现「带入中场巡查记录 N 条，最后出现范围收窄……」；搜寻计划把场务曾确认拥挤的区域加权置顶（经理端事件详情可查看被带入的逐条巡查记录）。
7. **场务**：找回任务页接单 → 选分区「未发现」提交，观察时间线与（散场阶段的）出口拦截重算。
8. **服务台**：三项全部勾选（豆包未授权临看）→ 提交后决定为**通知家长到服务台** → 「家长已当面认领」关闭事件；家长端同步显示团聚。
9. **经理**：推进到「散场」。家长端切到 `DD20260910002`（小糯米）报案（最后位置选互动区）：
   - **安保端**：北/西出口因场务久未巡查自动拦截，东出口刚巡查过暂不拦截；让场务到东出口打卡"未见"后，东出口立即升级拦截（巡查位置 → 拦截联动）。
10. **服务台**：这次只勾座位/家长、**衣着特征不匹配**并填不符点 → 自动**升级广播**，横幅文案变为「寻人更正」并写明真实衣着；可「再播一次」看次数累加。
11. **安保端**：申请监控调阅 → 填写警情后「报警」→ 全部出口强制拦截，家长通知方式变为专人陪同同步警方。
12. **经理**：「结束本场」→ 页面底部出现**复盘**：走失按入场/中场/散场分布柱状图；除站位/厕所/出口建议外，被反复触发且确认过拥挤的区域会生成 **场务排班**（下一场中场提前到位）与 **临时指示牌位置**（家庭厕所/卖品区入口增设指示牌）两类建议。

## 四、协同规则如何落到代码

| 需求 | 实现位置 |
|---|---|
| 高风险家庭评估 | `src/domain/engine.ts → assessRisk`（年龄/单家长/未授权临看/缺特征/家庭标记加权） |
| 入场后进入当场安全列表 | `stores/show.ts → admitByOrder` + 闸机视图安全列表（只含 `admitted`） |
| 中场重点巡查区域 | `recommendPatrolZones`（拥挤度 × 距上次巡查分钟数） |
| **中场休息高风险预警** | `scoreIntermissionAlert` / `buildIntermissionAlerts` / `reconcileAlerts`：按座位分区聚合**儿童年龄、座位距最近出口、单人带娃、家长报备离座未归、周边厕所/卖品拥堵**五因子打分排序，保留巡查历史并在升级时累计触发次数 |
| **确认拥挤 → 安保临时分流** | `alertCheck`（场务确认）→ `planDiversions`（拥堵功能区→最近出口），安保端 `DiversionChannel` 面板与地图流动箭头，可关闭 |
| **报案带入巡查记录、收窄最后出现范围** | `selectAlertSightings`（时效+邻近+确认拥挤强线索）→ `planSearchZones(..., sightings)` 对确认拥挤区加权、刚巡查正常区降权 |
| **反复触发 → 下一场排班/指示牌** | `alertBasedReviewSuggestions`（triggerCount≥2 → 中场固定场务提前到位；confirmCount>0 → 拥堵区入口增设临时指示牌），由 `reviewShow` 汇总 |
| 找回任务生成与最近派单 | `planSearchZones` + `nearestStaff`（地图坐标距离，忙碌者不参与，可改派） |
| 场务巡查位置影响出口拦截 | `planExitInterceptions`（超过盲区时长/排查未见的出口自动拦截） |
| 服务台三项核验三分支 | `verifyDeskCandidate`（全匹配+授权→护送；全匹配未授权→家长到台；任一不符→广播） |
| 核验结果影响广播与家长通知 | `buildBroadcast`（特征不符出"寻人更正"口径）、`parentNotifyWay` |
| 散场拦截/监控/警方同事件 | `Incident` 聚合 `interceptions / cctv / police / broadcast / timeline` |
| 复盘按入场/中场/散场统计并给建议 | `reviewShow`（经理页柱状图 + 站位/厕所/出口三类建议） |

纯领域逻辑均有单测（`src/domain/engine.test.ts`），完整跨角色链路见 `src/stores/show.test.ts`，六视图渲染冒烟见 `src/tests/smoke.test.ts`。

## 五、验证方式（= 宿主 docker compose up）

本工程的验收标准是 **compose 启动健康 + 关键业务流可在浏览器走通**：

```bash
docker compose up -d --build
docker compose ps                 # STATUS 应为 Up (healthy)
docker compose port app 8080      # 取实际宿主映射端口
curl -f http://host.docker.internal:$(docker compose port app 8080 | cut -d: -f2)/healthz
# 浏览器打开 http://host.docker.internal:<端口> 按上面"演示动线"操作
docker compose down               # 验证结束释放资源
```
